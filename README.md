# Портфолио Марии Першиной

Статический сайт на Astro и TypeScript. Требуется Node.js 24 (см. `.nvmrc`).

## Локальная работа

```sh
npm ci
npm run dev
```

Откройте адрес из вывода Astro, по умолчанию `http://localhost:4321`. Рабочий просмотр показывает места для недостающих изображений и закрыт от индексации. `npm run check` проверяет типы. `npm run build` генерирует сайт в `dist/`, а `npm run preview` позволяет проверить эту сборку локально.

Если в облачной машине домашний каталог недоступен для записи, укажите кеш npm внутри рабочего пространства: `npm ci --cache /workspace/.npm-portfolio`.

## Профиль и фотография

Профиль, контакты и видимость черновиков редактируются в `src/data/profile.ts`. Положите согласованный портрет в `src/assets/portfolio/` и импортируйте файл в профиль:

```ts
import portrait from '../assets/portfolio/maria-pershina.webp';

// В объекте profile
portrait: { image: portrait, alt: 'Мария Першина' },
```

Telegram и Max добавляются в массив `contacts` как объекты с полями `label` и `href`. Для предоставленного резюме используется такое же поле `resume`.

## Кейс

Добавьте файл `src/content/cases/<slug>.md`. Первые строки содержат метаданные, дальше идёт текст с заголовками от `##`. Путь к изображению указывается относительно файла кейса.

```yaml
---
slug: editor-icons
title: Редизайн иконок для текстового редактора
summary: Обновление иконок редактора и рекомендации по проектированию новых.
cover: ../../assets/portfolio/editor-icons-cover.webp
coverAlt: Краткое описание интерфейса на обложке
status: draft
showOnHome: true
order: 30
---
```

Добавьте текст и согласованную обложку, затем установите `status: published`. Astro создаст страницу `/cases/editor-icons/`. Необязательные поля `role`, `tags`, `year` и `readingTime` (в минутах) появятся в шапке кейса при заполнении. Встроенные Markdown-изображения из `src/assets/portfolio/` получают оптимизацию Astro. Для подписи и широкого изображения можно использовать элемент `figure`; готовый оптимизированный файл при этом положите в `public/` и задайте изображению `alt`, `width`, `height` и `loading="lazy"`.

Черновики не получают отдельного URL. `showOnHome: false` скрывает отдельную карточку, `showDraftsOnHome = false` скрывает все черновики. В статической сборке черновик отображается на главной только при наличии обложки.

## Концепт

Добавьте JSON-файл в `src/content/concepts/` с полями `slug`, `title`, `order` и массивом `images`. У каждого экрана задайте `src` (путь к локальному файлу относительно JSON), `alt` и `caption`. `summary` и `prototypeUrl` необязательны. Для примера структуры см. `editor-start-page.json`. Концепт попадёт в статическую сборку после добавления всех изображений. Нажатие на экран открывает увеличенное изображение, Escape закрывает просмотр.

## Статическая сборка

После согласования домена скопируйте `.env.example` в `.env` и укажите `SITE_URL` для абсолютных адресов canonical и Open Graph. Перед публикацией проверьте актуальность самопрезентации, права на портрет и рабочие материалы, отсутствие конфиденциальных данных на скриншотах и корректность контактов. В текущей версии текст о редакторе и описания работ взяты из ТЗ. Чтобы завершить наполнение, нужны портрет, полный кейс об иконках, обложки, два экрана концепта и ссылки Telegram и Max.

Для GitHub Pages workflow `.github/workflows/pages.yml` собирает и публикует сайт при обновлении `main`. В **Settings → Pages → Source** должен быть выбран **GitHub Actions**. Адрес и путь берутся из настроек Pages. Чтобы воспроизвести сборку сайта репозитория локально, запустите `SITE_URL=https://pershmary.github.io BASE_PATH=/portfolio npm run build`.
